# 架构

- packages/core 包含生活日、数据校验、量规、规划和共享业务写入。
- plugins/obsidian 使用 ItemView、Vault、系统主题和内置 Lucide 图标。核心路径不依赖 Node 或网络。
- plugins/dsh 提供 MCP stdio 插件，DSH 使用官方客户端加载。主机只挂载 LifePilot 的业务数据目录。MCP 写工具提交提案，Obsidian 经用户确认后应用。
- 业务目录下按实体保存不可变 Markdown 修订。每次写入携带父修订，以独立文件交给 Fast Note Sync。多端同时更新会产生可见分支，选择版本后写入合并修订。日记另存，避免进入 MCP 数据路径。

## 业务写入

修订格式为 `<实体>/<键>--<UUID>.md`，含可检索的 Properties 和一个 JSON 代码块。JSON 记录格式版本、业务键、父 ID、时间与经 Zod 校验的实体快照。日键为生活日，周键为周一，量规键为 `active`，提案键为请求 UUID。

同一进程依次写入，使用预期父修订拒绝过期操作。并发设备分别发布新文件，保留分支。父文件晚到时显示缺失，拒绝继续在不完整历史上编辑。合并修订引用全部分支。备份在写入前验证记录和 ID，追加同一备份可重试。

原计划、当日量规、入睡目标的绝对时间随生活日持久化。拆分保留原总量，替换保留原权重，额外成果与历史修订独立。报告只统计已解析的生活日，每日分数从成果与行为重算，带待录项的结算单列。周目标按有效成果折算分钟统计，实际用时另计。

提案绑定当时的日修订。批准后先写业务数据和已应用提案 ID，再更新提案状态。若两步之间中断，重试会看到已应用 ID，只补提案状态。文件同步负责传递提案和结果。日记位于独立目录，不进入业务备份或 MCP 工具输入。
